# CLAUDE.md — ГПР по напольному покрытию (ARDHANA)

Этот проект — лёгкий редактор графика производства работ (ГПР) по плитке/полам.
Серхио надиктовывает даты, ты правишь данные, он смотрит результат в виде простого Ганта
и в конце выгружает таблицу для загрузки в общий ГПР (Google Таблица).

## Карта файлов

|Файл                        |Роль                                                                              |
|----------------------------|----------------------------------------------------------------------------------|
|`schedule.json`             |**Единственный источник правды.** Все правки идут сюда.                           |
|`gantt.html`                |Визуализация: Гант + редактируемая таблица + экспорт. Самодостаточный, без сборки.|
|`ГПР_напольное_покрытие.csv`|Выгрузка для Google Таблиц / ГПР (создаётся кнопкой в `gantt.html`).              |

## Как смотреть результат

- **Быстро:** двойной клик по `gantt.html` (откроется из файла, данные из seed/localStorage).
- **Чтобы твои правки в `schedule.json` подхватывались по F5:** запусти локальный сервер из папки проекта:
  
  ```
  python3 -m http.server 5173
  ```
  
  и открой `http://localhost:5173/gantt.html`. Тогда страница тянет `schedule.json` живьём.
- Альтернатива без сервера: в шапке `gantt.html` → **Импорт JSON** → выбрать `schedule.json`.

## Схема данных (`schedule.json`)

```json
{
  "project": "ARDHANA Boutique Hotel",
  "work_type": "Напольное покрытие / плитка",
  "updated": "ГГГГ-ММ-ДД",
  "milestones": [ { "id": "mokap", "label": "Мокапы", "date": "2026-11-15" } ],
  "tasks": [
    {
      "id": "A2-ps",                 // уникальный, не меняй после создания
      "building": "Корпус А",        // Корпус А | Корпус Б
      "floor": "2 этаж",             // 2 этаж | 3 этаж | 4 этаж
      "units": "301–305",            // диапазон/перечень юнитов
      "stage": "Поставка",           // Поставка | Укладка | Подготовка
      "material": "Терраццо F2 / SPC",
      "start": "2026-08-04",         // ISO ГГГГ-ММ-ДД
      "end": "2026-08-12",           // ISO, >= start
      "status": "План",              // План | В работе | Готово | Критично
      "depends_on": "A2-ps",         // id предшественника или null
      "note": ""
    }
  ]
}
```

Цвета на Ганте: Поставка — оранжевый, Укладка — синий, Подготовка — серый.
Обводка: Готово — зелёная, Критично — красная. Вертикали: «сегодня» (красная), вехи/мокапы (фиолетовый пунктир).

## Конвенции голосового редактирования

Серхио диктует — ты сразу правишь `schedule.json`. Типовые команды и что делать:

- **«Сдвинь укладку 3 этажа корпуса А на неделю вправо»** → у нужной задачи `start` и `end` += 7 дней (сохраняй длительность).
- **«Поставку 4 этажа Б начни 20 октября, на 8 дней»** → `start="2026-10-20"`, `end=start+7`.
- **«Растяни укладку 2 этажа до 30 августа»** → меняй только `end`.
- **«Добавь подготовку основания на 2 этаже А, 3 дня перед укладкой»** → новая задача `stage:"Подготовка"`, привяжи `depends_on` укладки на неё при необходимости.
- **«Каскадом сдвинь всё, что зависит от поставки А3, на +5 дней»** → найди задачи с `depends_on`, ведущим (прямо или по цепочке) к `A3-ps`, и сдвинь их `start`/`end` на +5.
- **«Помести юнит 410 как критичный»** → найди задачу с этим юнитом → `status:"Критично"`.
- **«Удали строку поставки Б3»** → убери объект из `tasks`.

После любой правки:

1. Сохрани `schedule.json` (с отступом 2 пробела, UTF-8, без BOM).
1. Обнови `updated` на сегодняшнюю дату.
1. Кратко словами подтверди, что изменилось (1–2 строки), без длинных отчётов.

## Правила консистентности (соблюдай всегда)

- `end >= start` для каждой задачи. Если правка ломает — подтяни `end` к `start`.
- `id` уникален и неизменен; новые id давай говорящие: `A3-ps`, `B4-uk`, `A2-pod`.
- Укладка логически не начинается раньше поставки того же этажа — если видишь конфликт, скажи об этом, но **не двигай сам без команды**.
- Не создавай второй источник правды. Только `schedule.json`. Excel/CSV — это всегда выгрузка из него, а не параллельный файл для правок.

## Выгрузка в общий ГПР

1. В `gantt.html` → кнопка **Экспорт в ГПР (CSV)** → файл `ГПР_напольное_покрытие.csv` (разделитель `;`, UTF-8 с BOM — Google Таблицы и Excel читают кириллицу корректно).
1. Колонки выгрузки:
   `Корпус | Этаж | Юниты | Этап | Материал | Начало | Окончание | Длительность, дн | Статус | Зависимость | Примечание`
   (даты в формате ДД.ММ.ГГГГ).
1. В Google Таблицах: Файл → Импорт → Загрузить CSV → «Вставить на новый лист», разделитель — точка с запятой. Затем перенеси/смапь колонки в лист ГПР.

> Точный layout общего ГПР (порядок колонок, календарная матрица по неделям) пока не зашит.
> Когда Серхио даст структуру листа ГПР — допиши скрипт `export_gpr.py`, который читает `schedule.json`
> и формирует `.xlsx` ровно под те колонки/матрицу. До этого CSV выше — рабочий промежуточный формат.

## Контекст проекта (для осмысленных правок)

- Объект: **ARDHANA Boutique Hotel**, два корпуса — **А** и **Б**, этажи **2–4**.
- Типы юнитов: Светлый 25, Тёмный 25, Светлый 30, Лофт №1, Лофт №2, Люкс.
- Опорные вехи из ГПР: кладка 2 эт. до **10.07**, 3 эт. до **10.08**; штукатурка 2 эт. до **30.07**; **мокапы 15.11**.
- Логика пола: с/у — терраццо F2 везде; комната — SPC/паркет (в тёмном 25 — терраццо целиком). Стена с/у — плитка 800×600.
- Принцип Серхио: вести не всё разом, а **партиями по этажам/корпусам** — поэтому поставки разнесены по времени и привязаны к готовности под чистовую.

## Стиль работы

Быстро, по делу, без воды. Серхио постоянно двигает даты — оптимизируй под скорость итерации,
не перегенерируй лишнего. Подтверждай правки коротко и сразу показывай, где смотреть результат.
